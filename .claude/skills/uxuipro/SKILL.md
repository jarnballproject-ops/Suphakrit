# UX/UI Pro — Shabu Mood

ตรวจแล้ว**แก้ให้เลย** ไม่ใช่ออกรายงานให้ไปแก้เอง

---

## ก่อนเริ่มทุกครั้ง

1. อ่าน `frontend/src/index.css` ส่วน `:root` ให้จบก่อนแตะ CSS — ระบบ token มีครบแล้ว
2. อ่าน `frontend/src/components/shared/Bits.jsx` — มี component กลาง 17 ตัว **ห้ามเขียนซ้ำ**
3. เปิดไฟล์หน้าที่จะแก้ทั้งไฟล์ อย่าแก้จากการ grep อย่างเดียว

## ระบบดีไซน์ที่มีอยู่ (ห้ามสร้างใหม่ซ้อน)

### สี — dark-first ทั้งแอป

| กลุ่ม | token | ใช้ตอนไหน |
|---|---|---|
| ถ่านไฟ | `--e900`…`--e100` | สีหลัก ปุ่ม primary ตัวเน้น · `--e500` คือตัวหลัก |
| ทองเหลือง | `--g700`…`--g100` | ของพรีเมียม ป้ายเน้น เหรียญ/แต้ม |
| หยก | `--j600`…`--j400` | สำเร็จ ว่าง ผ่าน |
| กลาง | `--n900`…`--n0` | `--n800` พื้นหลัง · `--n700`/`--s1..s3` การ์ด · `--n50` ตัวอักษรหลัก |
| เส้น | `--line`, `--line-hi` | ขอบการ์ด เส้นคั่น |
| สถานะ | `--ok` `--warn` `--info` + `-soft` `-line` | พื้น/ขอบของ Note และ Chip |

**กฎเหล็ก:** ห้ามเขียนค่าสีดิบ (`#fff`, `rgb(...)`, `red`) ใน JSX หรือ CSS ใหม่ ถ้าไม่มี token ที่ตรง ให้ใช้ตัวใกล้ที่สุดแล้วบอกในรายงาน — อย่าเพิ่ม token ใหม่เองโดยไม่ถาม

**ตัวอักษรเล็กบนพื้นมืด** ใช้ `--e300` / `--n300` ขึ้นไป อย่าใช้ `--n500` กับ font ต่ำกว่า 14px จะอ่านไม่ออก

### Component กลางใน `Bits.jsx`

```
Countdown  TimeMeter  Chip  Step  QR  TableSlip  Loading  Empty
Note  Kv  Photo  Toaster  ConnectionBadge  ConnectionNote  MockBanner
```

Layout: `CustomerLayout` `CustomerBar` `ConsoleLayout` `TopBar` (ใน `components/layout/Layouts.jsx`)

เจอโค้ดที่เขียน empty state / loading / badge เองซ้ำกับพวกนี้ → **เปลี่ยนไปใช้ตัวกลางเสมอ**

### ปุ่ม

`.btn` + `--primary` `--gold` `--default` `--quiet` `--icon` `--sm` `--lg` `--block`

### ไอคอน — มี 34 ตัวใน `components/ui/Icon.jsx`

`home menuBook receipt wallet grid ticket chefHat tray chart tag settings search plus minus check close arrowLeft chevronRight chevronDown printer refresh trash logout clock users bell alert lock qr store flame sparkle cash card phone bank`

ต้องการไอคอนที่ไม่มี → เพิ่มใน `Icon.jsx` อย่า inline `<svg>` ในหน้า

## สามฝั่ง สามบริบทการใช้งาน — เกณฑ์ไม่เหมือนกัน

### ลูกค้า (`/order`, `/v/:token`, `/q/:token`, `/scan`) — มือถือ มือเดียว

- นั่งกินชาบู **มือมัน ร้อน ชื้น** → touch target **อย่างต่ำ 44×44px** ปุ่มหลักควร 48px+
- ปุ่มสำคัญต้องอยู่**ครึ่งล่างของจอ** นิ้วโป้งเอื้อมถึง
- `Step` (เพิ่ม/ลดจำนวน) ต้องกดพลาดยาก ระยะห่างปุ่ม + และ − อย่างต่ำ 8px
- ห้ามมี horizontal scroll ที่ความกว้าง 360px
- ตัวอักษรเนื้อหาอย่างต่ำ 15px ราคาและจำนวนอย่างต่ำ 16px

### พนักงาน (`/staff/*`) — แท็บเล็ต ยืน รีบ เสียงดัง

- ต้อง**กวาดตาเห็นใน 2 วินาที** ว่าอะไรต้องทำก่อน
- จอครัว `/staff/kds` อ่านจากระยะ ~70cm → เลขโต๊ะและชื่อเมนูต้องใหญ่ ตัวเลขโต๊ะอย่างต่ำ 20px
- สถานะต้องแยกด้วย**สี + ข้อความ** ไม่ใช่สีอย่างเดียว
- ปุ่มเดินสถานะ (`advance_order_item`) ต้องกดยืนยันยาก-ถอยกลับง่าย ไม่ใช่กลับกัน

### ผู้จัดการ (`/admin/*`) — คอม นั่งนาน ดูตัวเลข

- ตารางต้องมีหัวตารางค้าง (sticky) เมื่อเกิน 10 แถว
- ตัวเลขเงินชิดขวาเสมอ ใช้ `Kv` ที่ `mono = true`
- กราฟต้องมีป้ายบอกหน่วย

### จอทีวี (`/display`) — อ่านข้ามห้อง

- เลขคิวอย่างต่ำ 64px · ไม่มีอะไรเล็กกว่า 24px บนหน้านี้
- ห้ามมีปุ่มหรือของที่ต้องกด

## เช็กลิสต์ที่ต้องไล่ทุกหน้า

ไล่ตามลำดับนี้ หยุดแก้ทันทีที่เจอ ไม่ต้องอ่านจบก่อน

1. **สามสถานะครบไหม** — มีข้อมูล / กำลังโหลด (`Loading`) / ว่างเปล่า (`Empty`) / พัง (`Note tone="warn"`)
   หน้าที่มีแต่กรณี "มีข้อมูล" คือบั๊กที่รอเกิด
2. **สถานะว่างบอกทางต่อไหม** — `Empty` ที่บอกว่า "ยังไม่มีอะไร" เฉย ๆ ไม่พอ ต้องมีปุ่มหรือบอกว่าต้องทำอะไร
3. **ลำดับสายตา** — ของที่สำคัญที่สุดบนหน้านี้ใหญ่ที่สุดและอยู่บนสุดจริงไหม
4. **ระยะห่าง** — ของที่เกี่ยวกันชิดกว่าของที่ไม่เกี่ยวกัน (proximity) ถ้าทุกอย่างห่างเท่ากันคือยังไม่ได้จัด
5. **ปุ่มหลักมีตัวเดียวต่อหน้าจอ** — `btn--primary` สองปุ่มในจอเดียวแปลว่ายังไม่ตัดสินใจ
6. **touch target** ตามเกณฑ์ของแต่ละฝั่งข้างบน
7. **contrast** — ตัวอักษรกับพื้นหลังผ่าน 4.5:1 (ตัวปกติ) / 3:1 (ตัวใหญ่ 18px+ หรือหนา)
8. **ข้อความ** — ภาษาไทยเป็นประโยคที่คนพูดจริง ไม่ใช่ศัพท์ระบบ
   ❌ `visit_id ไม่ถูกต้อง` → ✅ `ลิงก์โต๊ะนี้หมดอายุแล้ว กรุณาสแกน QR ใหม่`
9. **เงิน** — ค่าในฐานข้อมูลเป็น**สตางค์** ต้องหาร 100 ก่อนแสดงเสมอ และใส่ `,` คั่นหลักพัน
10. **เวลา** — ใช้ `Countdown` / `TimeMeter` อย่าคำนวณเวลาเองในหน้า
11. **loading ต้องไม่กระตุก** — ของที่โหลดเสร็จแล้วอย่าให้ layout ขยับ (ใส่ min-height ไว้)

## วิธีทำงาน

### 1. ถามขอบเขตถ้ายังไม่ชัด

ผู้ใช้บอกชื่อหน้ามา → ทำหน้านั้น
บอกแค่ "ปรับ UI" → ถามว่าฝั่งไหน (ลูกค้า / พนักงาน / ผู้จัดการ / ทั้งหมด) **อย่าเดาแล้วรื้อ 25 หน้า**

### 2. อ่านก่อนแก้

เปิดไฟล์หน้านั้นทั้งไฟล์ + ส่วน CSS ที่เกี่ยวข้อง ดูว่าใช้ component กลางตัวไหนอยู่แล้ว

### 3. แก้

- แก้ JSX และ CSS จริง ไม่ใช่เสนอ diff ให้ไปทำเอง
- **ห้ามแตะ business logic** — `api/queries.js`, `api/mutations.js`, `context/StoreProvider.jsx`, RPC, หรือ SQL
  เจอบั๊ก logic ระหว่างทาง → รายงาน ไม่ต้องแก้
- แก้ทีละหน้า อย่ารวมหลายหน้าไว้ใน edit เดียว
- คอมเมนต์ภาษาไทยเหมือน codebase เดิม อธิบาย**ว่าทำไม** ไม่ใช่ว่าทำอะไร

### 4. ตรวจก่อนจบ

```bash
cd frontend && npm run lint && npm run build
```

ทั้งสองต้องผ่าน ถ้าไม่ผ่านต้องแก้ให้ผ่านก่อนรายงาน

### 5. รายงาน

ตารางสั้น ๆ: หน้าไหน · เจออะไร · แก้ยังไง
ปิดท้ายด้วยของที่**เจอแต่ไม่ได้แก้** พร้อมเหตุผล

โปรเจกต์นี้มี `shabu-mood-closing-plan.md` ที่กำหนดว่า**ห้ามเปิดงานใหม่ก่อนนำเสนอ**

> มันทำให้เดโม 7 ขั้นพังไหม

- **พัง** → แก้ทันที
- **ไม่พัง** → เขียนลงรายงานท้ายงาน **ห้ามแก้เอง**

การ "ปรับปรุงให้ดีขึ้น" ที่ไม่มีใครขอ คือสิ่งที่ทำให้โปรเจกต์นี้ปิดไม่ลงมาแล้วหลายรอบ
